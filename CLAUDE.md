# CLAUDE.md

Family photo memory timeline at `https://memories.patrickrobel.dk`. Private:
family-only login, photos never publicly reachable.

## Facts a session needs

- **Deploy**: Dokploy app `memories` (applicationId `aO-snDweznAl5O7zsPhHc`,
  project `memories`) on the Hetzner VPS (`ssh todolist-vps`,
  `178.104.231.9`). Docker build from `Dockerfile`, port 3000, domain via
  Traefik + Lets Encrypt. **Push to `main` = production deploy** (GitHub
  webhook; watch paths cover src/public/package/Dockerfile/drizzle, and note
  dotfiles do NOT match the globs). Dokploy API: token at `~\.dokploy\token`,
  header `x-api-key`, base `https://deploy.patrickrobel.dk/api`
  (tRPC-style, e.g. `application.deploy`, `deployment.all`). Panel:
  `https://deploy.patrickrobel.dk`.
- **DB**: Neon project `family-memories` (`wild-heart-81141768`, Frankfurt),
  reachable via `DATABASE_URL` in `.env`. Drizzle migrations in `drizzle/`;
  `pnpm db:generate` + `pnpm db:migrate`. Local dev and prod share this one
  database. Neon is managed through the Vercel org ("przrm's projects"), so
  new projects are created with `vercel integration add neon ...`, NOT the
  Neon console/CLI.
- **Auth**: Better Auth 1.6 (`src/lib/auth.ts`), passkey plugin from
  `@better-auth/passkey`, magic link via ZeptoMail (`src/lib/email.ts`).
  NO passwords, ever. Who may sign in: rows in the `members` table (invited
  in the app on `/members`, each tied to a Person), plus `SUPER_ADMIN_EMAILS`
  env, plus `FAMILY_EMAILS` env as a legacy fallback. Passkeys are managed on
  `/account`. Prod rpID is `patrickrobel.dk`. `src/db/auth-schema.ts` is generated by
  `pnpm auth:generate`; never hand-edit.
- **Access rules**: all in `src/lib/access-policy.ts` (pure, unit tested)
  and `src/lib/access.ts` (lookups). A vacation with its photos and notes is
  visible to super admins, its creator (`trips.created_by`) and members whose
  Person is tagged on it; to everyone else it does not exist (404, image
  proxy included). Every page, server action and API route starts from
  `getViewer()` / `getViewerOrNull()` and reads through `findVisibleTrip`,
  `findVisiblePhoto` or `visibleTripIds`. Never query trips, photos or
  comments unfiltered. Pushes about a vacation pass
  `onlyUserIds: tripAudienceUserIds(id)`.
- **App shell**: signed-in pages live in the `src/app/(app)` route group; its
  layout renders `AppNav` (top bar on desktop, bottom tab bar on phones), so
  pages never render their own site header. `/timeline` is home (`/`
  redirects). UI copy says "vacation"; routes and code say `trip`.
- **Person filter**: repeated `person` query params; several people means
  vacations with any of them.
- **3D**: `three` is only ever loaded lazily (`next/dynamic` with
  `ssr: false` or `import()`), never in a page's first-load bundle. The
  slideshow projector falls back to the plain fade without WebGL or with
  reduced motion.
- **Photos**: R2 private bucket (creds in env, `src/lib/r2.ts`). Upload =
  presigned PUT from the browser, then `/api/upload/finalize` (sharp 400/1200
  WebP + blurhash + BigDataCloud reverse geocode, idempotent via unique
  `r2_key_original`). Serving = authenticated `/api/img/[id]/[size]` proxy,
  `next/image` is intentionally unused (`images.unoptimized`).
- **Scrapbook rule**: every rotation/offset derives from stable ids via
  `src/lib/scrapbook.ts`. Math.random() in render paths causes hydration
  mismatches; never introduce it.
- **typedRoutes**: after adding a route, run `pnpm build` (or dev) once to
  regenerate route types, else `pnpm check-types` fails on Link hrefs.
- **Installable PWA**: one static manifest `public/manifest.webmanifest`
  (scope `/`, short_name "Memories") linked via `metadata.manifest` in
  `src/app/layout.tsx`, plus `appleWebApp` metadata and `src/app/apple-icon.png`.
  Icons regenerate from `src/app/icon.svg` via `node scripts/gen-app-icons.mjs`
  (sharp; also writes the monochrome `public/icons/badge-96.png`).
- **Web Push**: push-only worker `public/sw.js` (NO fetch handler, NO caching,
  path is permanent, served `no-cache` via `next.config.ts`; skipWaiting +
  clients.claim). Code in `src/lib/push/` (type registry in `registry.ts`),
  routes under `/api/push/*`, UI at `/notifications`. Types: `photos_added`
  (client fires once per upload batch), `trip_created`, `on_this_day`
  (`POST /api/cron/on-this-day`, `CRON_SECRET` bearer, idempotent per
  Copenhagen day). Sends only when `PUSH_SEND=1` (prod only; dev shares the
  prod DB) and VAPID keys exist. One prod VAPID keypair via
  `node scripts/gen-vapid-keys.mjs`; never rotate (kills all subscriptions).

## Commands

- `pnpm dev` / `pnpm build` / `pnpm check-types` / `pnpm test`
- `pnpm verify`: build, then type-check, then tests (the full gate)
- Env setup: `.\scripts\setup-env.ps1` (prompts only for empty keys)
- Prod env push: `.\scripts\push-dokploy-env.ps1`

## Conventions

- Mirrors PatrickRobelWeb conventions (Tailwind v4 CSS-variable theme in
  `src/app/globals.css`, shadcn base-lyra, `@/*` alias, lazy memoized db in
  `src/db/index.ts`).
- Patrick-run commands are ALWAYS committed scripts under `scripts/` (.ps1 +
  .sh), never inline one-liners.
- Single warm light theme; no dark mode in v1.
