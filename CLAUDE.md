# CLAUDE.md

Family photo memory timeline at `https://memories.patrickrobel.dk`. Private:
family-only login, photos never publicly reachable.

## Facts a session needs

- **Deploy**: Dokploy app `memories` (applicationId `aO-snDweznAl5O7zsPhHc`,
  project `memories`) on the Hetzner VPS (`ssh todolist-vps`,
  `178.104.231.9`). Docker build from `Dockerfile`, port 3000, domain via
  Traefik + Lets Encrypt. **Push to `main` = production deploy** (GitHub
  webhook; watch paths cover src/public/package/Dockerfile/drizzle, and note
  dotfiles do NOT match the globs). Dokploy API: token at `~\.dokploy\token`,
  header `x-api-key`, base `https://deploy.patrickrobel.dk/api`
  (tRPC-style, e.g. `application.deploy`, `deployment.all`). Panel:
  `https://deploy.patrickrobel.dk`.
- **DB**: Neon project `family-memories` (`wild-heart-81141768`, Frankfurt),
  reachable via `DATABASE_URL` in `.env`. Drizzle migrations in `drizzle/`;
  `pnpm db:generate` + `pnpm db:migrate`. Local dev and prod share this one
  database. Neon is managed through the Vercel org ("przrm's projects"), so
  new projects are created with `vercel integration add neon ...`, NOT the
  Neon console/CLI.
- **Auth**: Better Auth 1.6 (`src/lib/auth.ts`), passkey plugin from
  `@better-auth/passkey`, magic link via ZeptoMail (`src/lib/email.ts`).
  NO passwords, ever. Who may sign in: rows in the `members` table (invited
  in the app on `/family`, People tab, each tied to a Person), plus `SUPER_ADMIN_EMAILS`
  env, plus `FAMILY_EMAILS` env as a legacy fallback. Passkeys are managed on
  `/account`. Prod rpID is `memories.patrickrobel.dk` (never the bare
  domain: Todo and Hub use that, and Chrome then lists their passkeys here). `src/db/auth-schema.ts` is generated by
  `pnpm auth:generate`; never hand-edit.
- **Access rules**: all in `src/lib/access-policy.ts` (pure, unit tested)
  and `src/lib/access.ts` (lookups). A vacation with its photos and notes is
  visible to super admins, its creator (`trips.created_by`), members whose
  Person is tagged on it and members whose Person it is shared with
  (`trip_shares`); to everyone else it does not exist (404, image
  proxy included). Every page, server action and API route starts from
  `getViewer()` / `getViewerOrNull()` and reads through `findVisibleTrip`,
  `findVisiblePhoto` or `visibleTripIds`. Never query trips, photos or
  comments unfiltered. Pushes about a vacation pass
  `onlyUserIds: tripAudienceUserIds(id)`.
- **Families**: a family is a named group of People (`families`,
  `family_people`; a person can be in several). Only super admins create
  families, name them and assign people, on `/family` (tabs `#families` and
  `#people`, which also hold invites, logins, roles and person colours;
  actions in `src/actions/family.ts`, each returns a refusal to a non-admin).
  For a member `/family` is read-only and shows their own families.
  `canSeePerson` decides who exists for a viewer: a super admin sees
  everyone, a member sees themselves and people sharing a family with them.
  Every people list comes from `getVisiblePeople(viewer)` and
  `getViewerFamilies(viewer)` in `src/lib/family-queries.ts` (filtered in
  SQL). Never list the `people` table unfiltered for a page. The one name a
  member sees outside their families: people on a vacation they can open
  (tagged, uploader, commenter).
- **Tagging and sharing**: a member tags only people they can see
  (`refusedTags`); whoever may edit a vacation may remove any tag. "Share
  with people" lets the creator, a tagged person or a super admin show a
  vacation to people in their own families without tagging them
  (`setTripShares`: `findVisibleTrip`, then `canShareTrip`, then
  `planShareChange`; decisions in `src/lib/share-rules.ts`). A share from
  another family is never listed, counted or removed. Someone a vacation
  was only shared with cannot share it on. Creating a person is for super
  admins, on `/family`.
- **App shell**: signed-in pages live in the `src/app/(app)` route group; its
  layout renders `AppNav` (top bar on desktop, bottom tab bar on phones), so
  pages never render their own site header. `/timeline` is home (`/`
  redirects). UI copy says "vacation"; routes and code say `trip`.
- **Filter**: one filter on `/timeline`, `/map`, `/vacations`, `/slideshow`
  and `/countries`: repeated `family` and `person` query params, resolved by
  `resolveFilter` in `src/lib/person-filter.ts` (pure, tested) and drawn by
  `src/components/filter/PeopleFilter.tsx`. Every chip toggles; there is no
  "everyone" option. A selected family with no names selected means the
  whole family; several people means vacations with any of them. Pages use
  `resolved.selection` and `resolved.effective`, never the raw params: an id
  the viewer may not see behaves as absent. On `/countries` the bare URL is
  the viewer's own map and `pick=none` means nothing picked.
- **Person colours**: `people.color` holds a key of the fixed palette in
  `src/lib/person-colors.ts` (unique per person, set by a super admin on
  `/family`); `resolvePersonColors` gives a stable fallback for a null.
  "Shared" is one fixed colour. Map colours are hex: MapLibre cannot parse
  oklch.
- **3D**: `three` is only ever loaded lazily (`next/dynamic` with
  `ssr: false` or `import()`), never in a page's first-load bundle. The
  slideshow projector falls back to the plain fade without WebGL or with
  reduced motion.
- **Photos**: R2 private bucket (creds in env, `src/lib/r2.ts`). Upload =
  presigned PUT from the browser, then `/api/upload/finalize` (sharp 400/1200
  WebP + blurhash + BigDataCloud reverse geocode, idempotent via unique
  `r2_key_original`). Serving = authenticated `/api/img/[id]/[size]` proxy,
  `next/image` is intentionally unused (`images.unoptimized`).
- **Pins**: a vacation's pin on the globe and map is its cover photo's GPS
  (chosen cover, else the first photo), derived on read in
  `src/lib/trip-pin.ts`. `trips.lat/lng` is only the fallback when the cover
  has no location (set at upload from the first GPS-tagged photo). The
  `/map` tab is per photo instead: every GPS photo at its own spot, stacked
  when zoomed out (supercluster, `src/lib/photo-clusters.ts`).
- **Inferred locations**: a photo without GPS gets the spot of the photo
  taken closest in time the same day in the same vacation
  (`src/lib/infer-location.mjs`), flagged `photos.location_inferred` and shown
  as approximate. Runs after every upload; `pnpm fill-locations`
  backfills (dry run first, `FILL_LOCATIONS_UNDO=1` reverts). Setting a
  location by hand clears the flag.
- **Auto-visited**: a country found in a vacation's GPS photos, or, only
  when it has no located photo, at the vacation's own place (`trips.lat`,
  `trips.lng`; `vacationPoints`), is marked `visited` for
  every person tagged on it, with the year of the earliest such vacation.
  Planner in `src/lib/auto-visited.ts` (pure, tested), runner
  `syncVisitedForTrip` in `src/lib/auto-visited-sync.ts` (never throws; call
  it inside `after()`), triggered by upload finalize, a photo or vacation
  location change and a tag change. It only inserts: a row in any status is
  never changed, so a removed country (a `dismissed` row) stays removed.
  `pnpm backfill:visited` walks every vacation (dry run; writes only with
  `BACKFILL_VISITED_APPLY=1`). Scripts that load TypeScript run through
  `node --import tsx`.
- **Countries** (`/countries`): one map of visited countries per Person,
  table `person_countries` (one row per person and country; `status` is
  `visited`, `wishlist` or `dismissed`). Rules in `src/lib/access-policy.ts`:
  a viewer sees the visited countries and years of people they can see
  (`canSeeCountries` is `canSeePerson`); a map is edited by its
  own person or a super admin; wishlist and dismissed rows reach editors
  only; notes belong to the person when they have a login (a `members` row),
  to super admins when they do not. A tap on the map opens the card and
  marks nothing. Removing a visited country leaves a `dismissed` row;
  removing a wishlist row deletes it; an unconfirmed removal of a row with a
  year or a readable note is refused. The year limit is the current year in
  Copenhagen. Two or more people shown: each person's colour, "Shared" for
  countries several of them visited, read-only, visited rows only. `src/lib/country-queries.ts` picks
  columns and rows per tier in SQL: never select `note` and drop it in code.
  Write decisions live in `src/lib/country-actions-core.ts` (tested with a
  fake store); `src/actions/countries.ts` returns `{ ok, error }` and never
  throws a message (production masks thrown messages). Country keys are
  strings with leading zeros (`"036"`): never `Number()` one.
  `src/lib/country-catalog.json` is generated by
  `node scripts/gen-country-catalog.mjs` (world-atlas 50m shapes plus
  `world-countries`), never hand-edited; its test pins the UN member total.
  In client code MapLibre and the shapes are imported only in
  `src/components/countries/CountriesMapInner.tsx`, behind `next/dynamic`;
  the server loads the shapes in `src/lib/country-lookup.ts`.
  A GPS point maps to a country by point in polygon
  (`src/lib/point-in-country.ts`, nearest coast within `NEAR_COAST_KM`).
  The shapes file is stitched across the antimeridian and cut open at the
  pole: every ring goes through `src/lib/antimeridian.ts` first, on the map
  and on the server (without it the north lands in Russia). The share
  image is built in the browser from visited fills only (`shareFills`): the
  wishlist must never reach it.
- **Scrapbook rule**: every rotation/offset derives from stable ids via
  `src/lib/scrapbook.ts`. Math.random() in render paths causes hydration
  mismatches; never introduce it.
- **typedRoutes**: after adding a route, run `pnpm build` (or dev) once to
  regenerate route types, else `pnpm check-types` fails on Link hrefs.
- **Installable PWA**: one static manifest `public/manifest.webmanifest`
  (scope `/`, short_name "Memories") linked via `metadata.manifest` in
  `src/app/layout.tsx`, plus `appleWebApp` metadata and `src/app/apple-icon.png`.
  Icons regenerate from `src/app/icon.svg` via `node scripts/gen-app-icons.mjs`
  (sharp; also writes the monochrome `public/icons/badge-96.png`).
- **Web Push**: push-only worker `public/sw.js` (NO fetch handler, NO caching,
  path is permanent, served `no-cache` via `next.config.ts`; skipWaiting +
  clients.claim). Code in `src/lib/push/` (type registry in `registry.ts`),
  routes under `/api/push/*`, UI at `/settings` (Alerts section). Types: `photos_added`
  (client fires once per upload batch), `trip_created`, `on_this_day`
  (`POST /api/cron/on-this-day`, `CRON_SECRET` bearer, idempotent per
  Copenhagen day). Sends only when `PUSH_SEND=1` (prod only; dev shares the
  prod DB) and VAPID keys exist. One prod VAPID keypair via
  `node scripts/gen-vapid-keys.mjs`; never rotate (kills all subscriptions).
- **Version gate**: the Dockerfile stamps the commit (`scripts/build-info.mjs`
  reads `.git`, so `.git` must stay out of `.dockerignore`) into
  `NEXT_PUBLIC_COMMIT_SHA`; `/version.json` serves it. Signed-in pages poll it
  (`src/lib/use-app-version-gate.ts`) and show "A new version is ready"
  (`UpdateBanner`), or reload by themselves while hidden and idle. Anything
  holding work a reload would lose sets `data-unsaved-work` on its root.
- **Upload failures** leave a trace: presign and finalize log every refusal
  (`[upload] ... rejected`), and the phone posts its own failures to
  `/api/upload/report` (`[upload] client failure`). Read them with
  `docker service logs` on the VPS.
