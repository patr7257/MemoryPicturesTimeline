# Families Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Families, sharing a vacation with picked people, one person filter on every page, per-person colours, auto-visited countries and the Countries page fixes, shipped as one release on `feat/families`.

**Architecture:** Every access decision is a pure, unit-tested function in `src/lib/access-policy.ts`; `src/lib/access.ts` and a new `src/lib/family-queries.ts` only load facts and filter in SQL. The filter is one pure resolver in `src/lib/person-filter.ts` plus one presentational component. Map colours become data (feature state), and auto-visited is a pure planner behind a thin runner that never fails the request it follows.

**Tech Stack:** Next.js 16 App Router with typedRoutes, React 19, Drizzle on Postgres (Neon), Better Auth, Tailwind v4, MapLibre 5.24 via react-map-gl, vitest 4, `node --test` for scripts, pnpm 10.

**Spec:** `docs/superpowers/specs/2026-11-21-families-design.md`

Selected family ids not in `families` are dropped. `nameChips` = visible members of the selected families (people order), or every visible person when no family is selected.   - `toggleFamily(selection: FilterSelection, familyId: string, families: readonly FilterFamily[]): FilterSelection`: on adds it; off removes it and drops the selected names that are in no other selected family.
  - `togglePersonIn(selection: FilterSelection, personId: string): FilterSelection` (uses `togglePerson`).
